--- layout: default --- {%- comment -%} A Maintainer Profile page (#426): maintainers/.md, written and owned by that Maintainer on main. The card comes from _data/maintainer_profiles.yml, which the sync builds. That file holds the parsed fields and the portals derived from the Maintainer/s cells, since a profile never lists its own portals. Each portal shows its domain (the Entry's Domain cell or the Budget Portal's portal cell), falling back to the LGU name when there is none. The Maintainer's prose follows as `content`. Channel values become links only as http(s) URLs, scheme-less hosts like www.example.org (given https://), an email, or a Telegram username, so a profile can't inject another scheme. The prose below is the Maintainer's own markdown, rendered like any other page. Liquid and raw HTML in it are not sanitized here, and Jekyll 3 can't turn Liquid off per page, so a stray Liquid opening delimiter (double curly brace, or curly brace plus percent sign) in a profile breaks the site build. Reviewers must catch that on main before merging a profile. Don't write those delimiters literally in this comment either: Liquid still parses comment bodies, which is what broke the build once. A link's visible text drops "https://", "http://", "www." and a trailing slash (the guidelines' contact pattern: "dfa.gov.ph", not "https://…"); the href keeps the full URL. Emails are plain mailto: links with no obfuscation, by design: the source file is public on GitHub anyway. The support link (#498) is Personal Support: money to this person, not to a portal or the directory. The sync only lets an http(s) URL through, and it is shown with the funding disclaimer. {%- endcomment -%} {%- assign profile_handle = page.name | remove: '.md' -%} {%- assign profile = site.data.maintainer_profiles | where: 'handle', profile_handle | first -%} {%- comment -%} From 1024px the profile card is a left sidebar and the Maintainer's own text sits beside it, like the docs pages' contents sidebar, so the text keeps its reading width without leaving the rest of the page empty. Below 1024px the card comes first, so contact details lead on a phone. {%- endcomment %}
